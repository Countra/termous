# 云账号与同步界面

设备名称的编辑入口紧邻本机名称，采用带设备标识的紧凑弹窗，复用主题色和局部 SCSS Module。表单显示实时字符数，未改变名称时禁用保存；冲突或网络错误在表单内提供反馈及重新载入入口，不展示同步机制说明。

设备列表只为本机设备显示“编辑名称”，待授权设备也可编辑。名称去除首尾空白后为 1–100 个 Unicode 字符，不允许控制字符；保存通过 Core 的 `PATCH /cloud/devices/current/name` 提交账号代次和 `expected_revision`。名称版本来自 `name_revision`，独立于可信授权状态。冲突及网络失败保留草稿，主动载入最新名称才替换草稿和原始版本；账号切换丢弃迟到结果。云端 `devices_changed` 沿统一账号订阅更新各端列表，与配置自动同步开关无关。前端设备合同未提供名称版本时保留只读展示；此降级不代替云服务与 Core 的部署版本配套。

编辑面板同时核对当前认证状态、设备身份及可编辑状态；同一账号代次内发生认证失效、设备撤销或名称版本缺失时也会关闭面板。迟到的名称补读不能重新打开已失效账号的编辑面板。

左下角以原有 40px 单行展示头像与名称，未登录时展示“本地”，帮助图标保留在同一行右侧。向上展开的菜单与侧栏内容同宽，顶部展示账号摘要，下方提供个人资料、云同步、设备和设置入口；侧栏折叠时保留头像入口。账号在主内容区展示登录表单或“个人资料／云同步／设备／安全”页签，复用主题变量、AntD 和 Lucide。切换遵守现有草稿保护。

首次进入先展示登录选择，可点击“暂不登录，使用离线版”进入工作站。选择保存在本机浏览器偏好 `termous.ui.accountWelcomeCompleted.v1`，不进入配置备份；登录成功或主动进入其他页面后不重复引导。产品向导等待此选择完成，云服务未配置或读取失败也保留离线入口。账号页与侧栏共用应用层资料控制器，保存名称或头像后即时更新，退出或切换账号时清除旧身份。

账号页签由应用层统一控制，侧栏、通知和页面内切换共用同一状态。切换页签不重新挂载已访问的面板，保留当前资料草稿；账号绑定代次变化时重置面板，避免沿用旧账号的临时状态。

页面采用与设置中心一致的紧凑布局：账号概览、图标页签、独立滚动的业务面板。`features/cloud-account` 内的 `AccountSection` 只复用分区标题、说明、操作区和内容容器，不接管业务状态或 API；空态复用 `shared/ui` 的 `WorkspaceEmptyState`。样式使用现有明暗主题变量及共置 SCSS Modules，不改变其他页面。窄窗口中资料字段和列表操作自然换行，长账号名与设备标识截断后可查看完整内容。

认证表单按当前流程提供标题、说明和相关入口，注册、邮件验证和密码重置均可返回登录；切换流程保留邮箱，清除密码与验证串。设备、登录会话及轮换状态独立显示加载、读取失败和重试，读取失败不会伪报空列表，刷新不清空已加载记录或编辑输入。被撤销设备不展示批准操作，同步预览阻塞时展示原因。

资料的表单提交与保存按钮共用草稿、长度及忙碌检查。同步范围、差异汇总及冲突处理集中在独立弹窗；差异与冲突必须完整读取后才开放确认，不再叠加第二次确认弹窗。重新预览会清除旧结果，关闭弹窗、账号或 Core 切换后的迟到响应不得恢复旧预览，也不得继续开启另一账号的自动同步。确认时同时校验设备授权、恢复保障和忙碌状态，读取及提交失败在当前弹窗中显示并支持重试。

首次点击“启用同步”或自动同步开关直接进入预览，确认后执行同步并开启自动同步。已确认的设备可直接切换自动同步或“立即同步”；有冲突时进入同一预览弹窗。主动预览并确认已启用的工作区只同步本次变更，不改变自动同步选择。如果同步完成但保存自动同步设置失败，保留完成结果；重试只保存设置，不重复提交预览。未满足首次恢复保障时显示具体原因并提供安全页入口。

预览使用主题一致的紧凑表格和底部合计，不重复展示统计卡片；只展示有变更的类别，删除及冲突列按实际数量出现。表格不单独固定高度，长列表仅滚动弹窗正文。窄屏列标题使用带文字提示和可访问名称的图标，保留全部数值与删除提示。无差异时显示单一空态，首次开启自动同步的影响在确认前用一句话说明。

手动同步按明确的 `conflicts_pending` 业务错误打开冲突预览，不等待 WS 更新冲突数量，也不以缓存冲突掩盖网络错误。确认失败会作废当前界面的预览，须重新读取差异后才能再次提交；仅保存自动同步设置失败时仍只重试设置。自动同步开关写入复用账号页操作互斥并携带当前设置 revision，避免与退出登录或其他账号操作并发；恢复保障读取失败不阻止关闭已开启的自动同步。

个人资料包含名称（64 字）、简介（200 字）、公司／组织（100 字）及头像。头像支持最大 2 MB 的 PNG/JPEG，预览时居中裁剪为 256×256 PNG，点击保存才上传。Gateway 统一访问 Core 的 `/api/v1/cloud/profile`，更新携带绑定代次和资料版本，冲突保留草稿且不自动覆盖；重新载入会对未保存修改进行确认。切换账号或 Core 时取消旧生命周期，迟到请求不得回写当前资料。资料读取失败时账号摘要回退为邮箱，不阻塞原有云同步和设备功能。

云服务暂时不可达时保留账号、已取得的资料和编辑草稿，展示连接提示；Core 恢复会话后自动补读资料、设备、登录会话及轮换状态。读取补偿使用有界退避，写操作不自动重放；恢复连接不能清除失败的保存反馈，也不能替换草稿的原始资料版本。账号切换及同账号读取乱序时，迟到错误不得覆盖新状态。一次性刷新结果不明时保留账号页，由用户主动打开重新登录弹窗；明确的认证失效才回到登录界面。

登录完成后先授权可信设备，再预览并确认同步范围；不会自动上传本机配置。同步面板展示最近成功时间、待处理数量、冲突数量及自动同步开关，详细差异和冲突在预览弹窗中处理。密码按原样提交，不裁剪空格。设备页主动申请，可信设备收到批准窗口，确认并提交单一证明后，新设备后台验证、解密、持久保存并领取。申请创建后，两端默认展示相同的八组配对码；批准前后配对码不变，不再双边点击。审批端显示新设备完成提示，请求端显示本机验证与保存进度；页面关闭不影响后台完成。安全页管理重新认证、登录会话、托管恢复及轮换。

已登录后的敏感操作共用一种验证表单：开启 2FA 只输入第二因子，未开启只输入密码；无法读取因子状态时显示错误和重试，不降级。托管恢复及启用只接受 TOTP。登录仍是密码后验证第二因子，恢复密钥与密码重置的额外邮箱确认保持各自用途。会话撤销及轮换可复用服务端仍有效的五分钟重新认证期限，专属操作不借用通用期限。响应不确定时查询原操作，不自动重放验证码。

## 二步验证

普通用户可在安全页启用 TOTP 验证器，并保存 10 枚一次性备用码。启用向导依次验证身份、扫描本地二维码或输入密钥、确认动态码及保存备用码；更换验证器先验证原有因子，新验证器确认成功前保留旧因子。启用、更换及关闭会退出其他登录会话；重新生成备用码只使旧码失效，保留登录会话。身份验证有效期使用服务器返回的截止时间，不以本地成功提示推断权限。

启用后，密码通过只进入二次验证步骤，动态码或备用码验证完成后才建立正式登录。等待时保留既有账号身份，不导航、不触发设备注册或同步；挑战过期可返回重新登录。网络失败不退出账号；一次性操作响应不明时不自动重放，登录需重新开始，设置操作补读当前状态。已开启但未收到备用码时，重新验证后生成新码，秘密不提供回读。

`entities/cloud` 定义两阶段登录与类型化因子合同，应用 Gateway 只访问受保护的 Core `/cloud/auth/login/verify`、`/cloud/auth/mfa/*` 及重新认证接口。因子设置不属于本机设置中心，不参与配置备份；二步验证不能单独代替设备授权，托管恢复须预先单独开启。

## 设备审批与托管恢复

`common/contracts/cloud-security.ts` 提供纯合同，`entities/cloud/model/security.ts` 严格解码。Gateway统一使用Core `/cloud/device-requests`、`/cloud/managed-recovery/*` 和受控policy/action入口。Renderer只接收状态、允许动作和展示摘要，不接收完整transcript、信封或长期秘密。新增可选 `pairing_code`，Core 在校验原始申请归属、公钥、nonce 和签名后，通过独立展示用途域计算；配对码仅标识申请，不替代身份验证或授信证明。历史 `fingerprint` 仍绑定完整审批材料，不能在旧 Core 缺少配对码时冒用；界面显示暂不可用及重读入口。

`AccountAuthorization`共用受控对话框；`AccountDevices`管理待办、初始成员复核与授权方式；`AccountRecovery`使用安全页全宽分区。设备名称、平台与来源紧凑展示，配对码采用默认展开的四列两行布局；审批页将拒绝与确认放在同一操作区，请求端无需填写身份表单。列表及等待对话框由实时提示补读，成功后不周期查询；只有失败使用有界退避。generation与生命周期丢弃旧结果。配对码不自动产生批准或核对证明；切换授权方式先明确取消。状态读取失败禁用关键决定，失败清空密码与OTP，不自动重放。

`AccountApprovalCoordinator` 常驻应用层，通过类型化失效订阅独立读取申请列表。可信设备收到可处理的新申请后立即更新待办并自动打开对应对话框，无需停留在设备页；当前页面和未保存草稿保持挂载。安全／恢复查询慢或失败不会拖住列表，第二因子状态未知时禁用验证并提供重试。关闭的申请在本次代次中不因重复提示或重连再次打断，多个申请依次展示；手动详情及通知共用同一弹窗入口。主机密钥审批优先时暂时隐藏设备审批，保留表单，结束后恢复。弹窗不自动核对、批准或启用同步。

批准响应丢失时先查询原申请，查询确认操作完成后清除旧失败提示，不重放验证码。同一状态的刷新仍保留真实失败原因。已批准或服务端已确认领取但本机密钥未就绪时，可重试完成同一授权；关闭弹窗后，设备列表仍保留本机未完成记录的详情入口。账号已失效或令牌刷新结果未确认时不提供领取重试。

正常连接时，Core 的单条云端 WebSocket 收到安全提示，立即通过本地 WS 失效审批列表，同时独立补读和保存安全事实。`useCloudChanges` 按 generation、区域和受控操作 ID 定向补读个人资料、MFA、设备、会话、授权、恢复、工作区和轮换。申请列表与详情不周期查询；首次、重连、权限变化、失效提示和用户操作触发补读。通知到达即更新相关列表和详情，不等待状态防抖；倒计时只更新本机显示。资料补读保留编辑基线和草稿；授权补读不默认核对指纹；重置结果补读不执行切换，同版本保留用户确认，版本变化清除旧确认。

安全摘要读取期间收到的新提示合并为一次补读，旧结果及错误不覆盖刚完成操作后的状态；切换账号或Core后，旧回调不能借用新请求生命周期。授权到期、终止或验证权限撤回时立即隐藏身份表单并清理密码／OTP草稿，不等待倒计时结束。

恢复默认关闭，必须可信设备已验证密钥且账号开启TOTP。开启及领取明确接受平台具备恢复数据密钥的能力；备用码不能恢复，刚登录使用的TOTP须等下一枚。24小时换绑保护期、冻结或服务禁用显示具体原因。关闭并轮换先停止发放，再验证执行既有轮换，离开不伪报轮换完成。

保留本机可信身份时，会话失效页面提供主动紧急停止入口；它只降低发放权限。安全提醒独立于AutoSync，通知携带受控操作ID/kind，点击直接打开对应详情。旧账号目标不自动执行写操作。原生投递和窗口唤起继续使用现有Electron通道。

种子与备用码仅短暂存在当前组件内存，不写日志、缓存或消息中心。复制和下载需要用户明确操作，下载后释放 Blob URL；取消、离开、绑定到期或代次变化即销毁敏感界面，避免退场动画暂留秘密。到期前已经发出的确认仍等待正式结果：明确成功时展示一次性备用码，结果不明时仅读取状态。向导冻结开启时的因子状态与版本，外部版本变化会退出旧草稿，不自动改用新版本提交。状态读取失败不会当作未开启，账号切换会拒绝迟到结果。

## 工程边界

- `common/contracts/cloud.ts`：纯状态、受控目标及输入合同。
- `entities/cloud`：严格解码、Gateway 和按代次／版本合并状态，拒绝迟到请求及旧账号事件。
- `features/cloud-account`：认证、预览确认、设备和安全操作。
- `pages/account`：复用统一页面外壳组合业务面板。
- `app/data-runtime`：受本地 token 保护的 Core 客户端；Renderer 不直接访问云服务器、令牌或私钥。
- `app/main`：全局 WebSocket 和按数据集刷新目录；遇到编辑草稿先延迟，保留会话与选中状态，不整页重载。

数据集失效到达后立即局部刷新；在途刷新期间合并后续提示，完成后立即继续。进入编辑永久作废此前读取，退出编辑不能恢复旧快照的写入权限；解除草稿保护后立即补读，不等待网络退避。成功空闲时没有周期刷新。只有读取失败且仍有待办时使用一至三十秒退避；更换 Core 后旧刷新不能阻塞新连接或重新排入旧数据。

状态版本合并和数据集失效分别处理：同一绑定下，较旧版本事件中的数据失效仍会触发局部刷新；旧绑定事件继续丢弃。HTTP 调用方取得合并后的当前状态，通知跳转不会使用被状态层拒绝的旧账号结果。切换 Core 时，旧请求不会清除新请求的忙碌状态或回写错误。

系统通知复用现有消息中心和 Electron 投递策略，增加“云服务”分类。首次／手动同步、认证失效、冲突和关键设备操作进入历史；普通后台成功不产生弹窗。点击直接定位账号页签，旧绑定目标退回保留摘要，不自动登录或重试。

自动同步通过统一设置中心 `cloud` 模块管理，`backup: exclude`。应用组合根必须向账号页传入同一 `SettingsGateway`，由页面向同步面板提供设置上下文；缺失快照或读取失败时显示重试，不以无反馈的禁用开关代替错误状态。服务器 origin 从 Core 数据目录的 `.termous-service.conf` 读取，不出现在设置页，不进入备份。Core 未配置或离线时，已有本机功能保持可用。

开启后，Core 在本地配置保存进入变更日志时主动调度，等待 500 毫秒合并连续修改，最长等待两秒启动；不再依赖五秒扫描。云端提交成功后提示其他已授权设备主动拉取，接收端仍须开启自动同步并已确认范围。前端不承担上传调度，继续按 Core 应用完成的数据集事件局部刷新，编辑草稿未关闭时保留刷新待办。普通同步不新增消息中心记录或系统弹窗；断线、冲突和失败仍按原有状态展示。

## 验证

账号 UI 测试覆盖登录不自动同步、未配置空态、通知页签定位及账号切换。实体测试覆盖旧代次、版本回退和非法合同。继续执行全量 Node／Electron 和 UI 测试、lint、typecheck、架构检查和构建。系统通知、Keyring 和窗口唤起的实际体验需分别在 Windows、macOS、Linux 打包应用验收。

## 个人恢复密钥文件

设置／更换只需验证身份、下载 `.torkey` 文件，再点击“已保存，启用”，不回填随机分组。完整文本默认收起，可查看或复制。文件为 Core 生成的版本化 UTF-8 JSON，不由页面拼接账号和密钥材料。

文件读取与远端操作分别管理生命周期：入口禁用或组件卸载会取消尚未提交的读取；关闭弹窗、切换 Core／账号及关闭后重新打开均使旧读取结果失效，退出动画不能延长授权操作的有效期。设备替换集合在实际提交时读取，文件与旧文本输入共用重复提交保护；旧文本重试清除先前输入错误，结束后清空秘密。

新设备授权和归档取回共用 `AccountRecoveryKeyInput`：选择或拖入单个文件后自动读取与校验（最大 4 KiB）；旧版文本保留在次级入口。文件仅提交给本机 Core，校验服务／账号／目标工作区／恢复版本及密码学证明，不上传文件到云端。归档仍先预览，再明确确认应用，不隐式开启同步。

组件卸载、关闭和账号切换清除表单并取消文件读取；同一文件允许重新选择，忙碌期间不重复提交。业务错误在弹窗内显示，不用文件读取错误覆盖远端错误。下载仅表示交给平台保存，最终由用户明确确认已保存；打包应用的文件对话框需独立验收。完整合同见相邻 Core 的 `docs/personal-recovery-file.md`。
## 扫码登录交互补充

登录面板默认密码方式，通过并列切换进入 `AccountQRLogin`。二维码保持高对比和完整留白；扫描后展示核对码与手机确认状态，过期只提供显式刷新。切回密码取消尚未批准的请求，已批准流程交由 Core 完成。管理后台不使用该组件。

`CloudGateway.qrLogin` 仅调用本机 Core，Renderer 不持有所有权或云令牌，不自行轮询服务端。页面订阅 generation 对应的状态，隐藏时退订主动读取；StrictMode 重附着不重复创建。中英文和深浅主题复用现有设计令牌。

相关 UI 测试覆盖单次创建、账号绑定、已批准退出、过期刷新；In-app Browser 使用真实组件与合成 Gateway 验证默认密码、切换、倒计时、核对码和主题。该 UI 验收不代表真实云账号已经完成跨端登录；协议与数据库闭环由独立 Go 集成测试覆盖。
