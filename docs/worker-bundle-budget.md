# Worker 构建体积与依赖检查

`scripts/agent/check-worker-bundle.mjs` 检查 Agent 和终端补全 Worker 的完整本地依赖闭包，共享代码块只累计一次。此检查属于开发与构建流程，不限制模型上下文、工具结果、文件大小或 Worker 运行内存。

## 检查行为

| 检查项 | 处理方式 |
| --- | --- |
| 缺失必要模型适配器、引入未经审核的依赖或非目标 Provider | 构建失败 |
| 产物缺失、空文件、符号链接或本地引用超出产物目录 | 构建失败 |
| 完整闭包超过体积参考值 | 输出实际字节数、参考值与超出比例，构建继续 |

体积参考值集中维护在脚本顶部的 `workerBundleSizeReferences`：

- Agent Worker：2 MiB。
- 终端补全 Worker：768 KiB。

两个入口承担的职责不同，分别设置参考值。参考值为正常功能扩展预留空间，不是运行时内存预算或永久上限。脚本不会自动提高参考值，也不按单次构建结果更新基线。

## 手动复查与调整

1. 查看改动及构建输出，确认增长来自必要业务代码，或定位误引入的依赖、重复代码和未使用模块。
2. 保持合理模块边界。不得为了满足数字删减功能、改写为难维护代码，或通过遗漏共享代码块、随意外置依赖绕过统计。
3. 必要功能或依赖升级造成持续增长时，结合相关功能回归与真实 Worker 启动、内存测量判断是否需要调整参考值。使用相同环境比较；产物字节数不能代替运行性能结论。
4. 手动修改相应入口的参考值，在同一改动说明增长原因、依赖审查和实际验证结果。未执行的性能或持续运行测试必须明确列出。一次提示不要求立即提高参考值。

依赖允许名单与体积参考值独立。新增必要依赖时，应审核其用途、依赖闭包和进程归属后修改名单；提高体积参考值不会使未知依赖自动通过检查。

## 验证入口

```sh
node --test scripts/agent/check-worker-bundle.test.mjs scripts/ci/clean-electron-output.test.mjs
pnpm run build:renderer
pnpm run test:agent-workers:electron
```

正常生产构建已包含体积提示与依赖门禁，不需要新增 CI 流程。Electron 验收使用隔离服务验证真实 Worker 加载、IPC 和失败退出，不能替代完整业务或持续运行性能测试。预算检查自身的改动不改变产品 Worker 的运行逻辑。

## 本轮复查结果

2026-10-29 移除了为旧体积上限增加的能力目录压缩包装与压缩副本，恢复直接读取生成的 JSON。保留审批字段的小型生成投影，用于维持合同层与工具层的依赖方向。

隔离生产构建测得 Agent Worker 完整依赖闭包为 1,712,009 字节，终端补全 Worker 为 476,082 字节。Agent 比旧硬上限多 8,073 字节，无需删减功能或增加运行时解压逻辑。依赖允许名单未扩大。

生产构建、依赖检查和 Electron 开发／ASAR 实际加载均通过；本次未测量启动耗时和长期内存，体积结果不代表性能结论。验证明细见 [本地工具复查记录](../../backend/docs/agent-local-tools-validation.md)。
