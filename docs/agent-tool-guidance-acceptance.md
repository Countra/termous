# Agent 工具引导与停止回归记录

验收日期：2026-10-28。涉及 `backend`、`web`、`termous-skills`；公共 MCP 参数、数据库迁移和 runtime 协议版本（17）不变。

## 修改范围

- 桌面绑定与历史目标恢复共用能力目录入口，同时提供截图、链式执行及常用单动作声明。截图和 Skill 入口补齐链式工具；声明加载不连接桌面、不申请控制、不派发输入。
- 成功输入的 `recovery: none` 表示无需恢复，`accepted` 表示本次输入已接收。未知派发、清理不确定、审批及失败保留原有恢复含义。
- 正常后台回执提供独立工作、等待和查询的可选建议，不再附带要求立即调用 `get` 的具体前置调用。工具选择仍由模型决定。
- Core 保存停止屏障后，使用已有独立控制通道通知 Worker。浏览器不再依赖 Electron IPC；停止请求失败后可以重试，已领取但响应丢失的停止请求可以重新投递。Worker 退出前不宣称 Run 已停止。
- 批次回执采用有界字段投影，避免通用文本截断破坏结构化终态。Run 结束后补读最终账本，迟到的运行快照不能覆盖终态。
- Worker 在停止时尚未写入 `task_result` 的历史记录，从原 Run 的任务账本只读补齐展示终态。按会话、Run、工具调用和执行 ID 核对归属，不改写原消息或恢复授权。
- 停止和批次取消按钮只在本次请求在途时禁用，不能因为一次失败或 `stopping` 状态永久失效。

没有新增话术匹配、意图路由、重复调用计数、强制选工具或自动重放。

## 本轮复查修复

- 历史账本补齐终态时，同时更新外层工具失败标记，避免取消、停止、未知输入、清理或回执持久化故障仍显示成功。保留原消息、原调用和原执行身份，不修改存储的原始回执。
- 实时快照只更新当前 Run 的 assistant 消息及匹配执行 ID 的 `execute`，不能串到旧 Run 的同名工具调用，也不能将终态退回运行中。
- 原执行已被账本补齐终态但没有图片时，仍可采用同一执行后续查询或等待回执中的真实图片来源；不同会话不能相互补图。
- 复现并修复了实际页面缓存与无缓存投影不一致的问题：完成观察在后续消息中到达时，原执行的状态与图片也更新。按不可变消息弱引用缓存索引，正常流式输出不反复解码全部历史回执，未变化的展示继续复用。
- 取消请求失败后仍可重试；收到终态后移除旧的“取消未确认”提示。补充 Core 托管运行时不调用 Electron IPC、`stopping` 可重试的控制器回归。

以上改动限于既有发现、控制、历史查询和展示职责，没有增加新的执行器、公共接口、协议版本或数据库迁移。本轮没有重新进行 RDP 实机操作；下方保留此前真实测试及未完成项，不将自动化结果作为实机覆盖。

## 模型表现与覆盖缺口

短链和等待用例中，模型能够发现并使用链式执行与等待工具。两步自然完成用例中，模型重复查询了原批次，全轮产生 16 次模型请求；它还在没有取消事件证据时声称验收人员已点击取消。该表述不作为验收事实。

据此移除了正常运行回执中具体 `get` 前置调用的引导，保留可选查询，并明确等待工具可以挂起而无需反复查询。该调整的自动化回归通过；其最新实机效果尚未验证，不能宣称已消除模型的错误选择。

重启开发 Core 后，后续 RDP 连接在首次输入前失败，错误为 `REMOTE_DESKTOP_TARGET_CONNECT_FAILED`，原生诊断为 `ERRCONNECT_POST_CONNECT_FAILED`。模型回执与远程桌面页的重连均确认连接失败；这不属于已验证成功的输入或取消场景。

因此仍需在 RDP 恢复后完成：

1. 展开原批次卡片，在两步之间的长等待期间实际点击取消，确认第一步 `accepted`、第二步 `skipped`，并确认按钮及卡片终态。
2. 用同一场景复测最新可选等待说明，记录模型是否选择等待或独立工作；不按固定轮数强制选择工具。

没有用本机桌面替代这些缺失的 RDP 实机覆盖。取消失败后重试、终态不倒退和第二步跳过的展示已有自动化验证，但不等同于上述实机验收。
