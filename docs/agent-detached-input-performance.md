# AI 助手独立窗口输入延迟回归（2026-10-24）

## 原因与修复边界

主窗口已有消息投影缓存，但独立窗口接收分区后，`restoreAgentSurface` 每次都重建全部消息对象及片段数组。一次按键会先触发本地草稿回显，再触发宿主确认，两次更新均使消息区的 React memo 失效。侧栏的 `pendingIds` 也被反复还原为新 Set，导致会话列表重新渲染。

回归用例确认：12 次输入及对应确认额外触发 24 次历史消息区渲染；修复后为 0。真正的正文更新仍触发消息区更新。

- 接收端按消息元数据和片段引用还原，只替换实际变化的消息；消息顺序、删除、状态及流式正文正常更新。
- 本地输入复用已经还原的宿主模型，不遍历历史分区；待处理集合使用弱引用缓存，保持侧栏引用稳定。
- 远端操作适配器在独立的浅层视图上注入回调及乐观草稿，避免污染复用快照。确认后的正文、撤回的能力及排队问题编辑不会残留在原快照中。
- 消息缓存只保留当前 workspace/archive 分页窗口，移出窗口或关闭页面时释放；没有增加跨会话历史缓存。
- 复查后，未变化的完整消息先比较片段分区引用，命中时不再分配临时片段数组及元数据副本；暂缺片段仍按现有规则重建，补齐后恢复顺序。

未改动输入回执、序号、IME 组合、提交前确认、会话归属及窗口交接协议，也没有增加输入防抖或修改推理与工具流程。

## 原生测量

Windows、Electron 43.1.1、生产 renderer，使用真实页面组件、独立窗口管理器及 IPC；主进程为隔离验收宿主，数据为内存夹具。80 个会话、200 个历史片段，打开独立窗口后隐藏主窗口，每次通过 Chromium 原生文本输入接口插入一个字符。

延迟从 `input` 事件开始计至下一次 `requestAnimationFrame`；不包含系统输入法候选窗口、键盘设备或操作系统调度之前的时间。整个草稿在小窗和收回后的宿主中逐字校验一致。不使用强制 GC。

| 场景 | 字符数 | P50 | P95 | 最大值 | 超过 50ms 的 renderer 长任务 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 修复前 | 624 | 30.4ms | 36.5ms | 46.8ms | 0 |
| 修复后 | 624 | 2.8ms | 6.4ms | 8.7ms | 0 |
| 修复后扩展输入 | 3,120 | 3.4ms | 6.3ms | 9.3ms | 0 |
| 复查补项后 | 624 | 2.8ms | 6.3ms | 8.8ms | 0 |

扩展输入约 49 秒，DOM 节点维持 2,358。小窗 renderer 私有内存采样峰值约 289.4 MiB，宿主约 202.2 MiB。加载和输入期间仍有堆分配及原生输入历史开销；该短测不能证明数小时内存平台或完整软件的 2 GiB 目标。

原始测量位于 `TEMP/detached-windows/input-baseline.json`、`input-fixed.json`、`input-long-fixed.json`，同名 PNG 为实际独立窗口截图。

复查采样为 `TEMP/detached-windows/input-review.json`。验收脚本现在明确等待 80 个会话和 200 个历史片段完成挂载；最终报告在草稿交接校验通过后发布，包含 `handoff=passed`。

## 重复执行

准备包含应用入口与 `scripts/agent/detached-preview.html` 的前端服务，默认地址为 `http://127.0.0.1:5183/`，然后运行 `pnpm run test:detached:input`。可用 `TERMOUS_INPUT_URL` 指定待测开发或生产预览地址（需以 `/` 结尾）。本轮使用隔离目录中的生产预览。

`TERMOUS_INPUT_SAMPLE` 指定报告名前缀，仅允许英文字母、数字、下划线和短横线，最长 80 字符，禁止作为目录路径使用。`TERMOUS_INPUT_ROUNDS` 为 1～250，默认 24（624 个字符）。扩展输入使用 120（3,120 个字符）。验收文件及 Electron 测试目录沿用 `TEMP/detached-windows`，pnpm 缓存不变。测试结束自动退出验收 Electron；前端服务由启动者清理。
