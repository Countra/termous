# 桌面观察到输入的工具导航

## 故障依据

2026-10-24 开发运行 `agr_ab176fd545625e12c5f623e2` 共调用工具 29 次，没有鼠标调用。请求用量记录中的 `effective_tools` 证明，整个循环没有提供 `termous.desktops.pointer.click` 声明。模型虽然可以主动发现它，但没有执行发现；多次声称将点击，实际仍发送快捷键。

问题涉及四处行为：

- 能力目录中 capture 的 `next` 为空，成功截图不能补齐输入选择；重复观察诊断也没有可加载的下一步工具。
- 内置参数简化提前返回描述，遗漏了原有的动作选择说明；普通成功回执采用精简导航，无法补回这些信息。
- 图片资源化后，画面指纹仍仅处理旧式 `image` 块。轻量 `resource_image` 被忽略，不同截图也会被当作相同观察。
- 成功输入直接退出重复检测。同一按键即使反复只有协议接收回执，也没有独立的观察与纠正提示。

这些证据能解释本次循环的实现缺口，不能据此断言模型在其他任务中永远不会主动发现鼠标，也不能把键盘协议接收解释为目标应用已响应。

## 实现边界

唯一能力目录仍为 `termous-skills/contracts/agent-capabilities.json`。成功截图按需加载点击、滚动、文字输入和快捷键；键盘输入之后提供截图、点击和原操作查询。只加载已授权且未被输入安全机制阻止的声明，不预先发送输入或申请权限。活动工具继续受原有 32 项上限约束。

内置简化声明保留观察和输入阶段的动作指引，内部附着、授权及请求身份仍由准备层管理。当前截图坐标使用 `coordinate_space=image`；原始桌面坐标使用 `desktop`。截图过期、人工收回控制和不确定输入继续由原有机制处理。

资源图片使用已校验的 SHA-256 内容摘要参与画面指纹；旧图片编码按同一内容摘要比较。资源 ID、截图 ID、时间和帧序号不表示任务进展。诊断不读取图片文件、不物化 Base64，也不常驻保存像素。

相同快捷键或单键操作连续收到 `operation.state=accepted`，且没有新的画面变化证据时，复用现有有界进展诊断提供下一步声明。不同按键、文字输入和不确定操作不混入这项判断。诊断仅提示，不增加强制输入次数上限、不自动点击或重放。所有计数、摘要和通知继续使用现有有界结构。

真实验收还发现未绑定目标时，模型把主机显示名称传作 host_id。connect 的简化声明与英文 Skill 补充了从主机列表获取真实 ID 的要求；不通过猜测名称映射或自动替换目标来掩盖错误。
