# 消息中心与系统通知

Core 是消息事实和已读状态的唯一来源。Renderer 与 Electron 分别订阅 Core WebSocket，不通过页面组件互相转发完成事件。现有 Agent 和文件任务执行、重试和 Toast 保持原有职责。

`common/contracts/notification.ts` 定义纯合同、解码、展示模板和受控跳转目标。`entities/notification` 合并权威快照与增量；`features/notifications` 负责订阅协调和本机偏好；`widgets/notification-center` 展示顶部铃铛和右侧抽屉；`app/notification-runtime` 装配订阅、状态操作与激活交接。设置页面以插槽装配通知设置，避免 feature 横向依赖。

`electron/notifications` 管理原生投递、偏好、Core 订阅和 IPC。只在主窗口最小化或隐藏时投递，失去焦点本身不触发。首次快照仅建立水位，重连补齐不超过两分钟的新结果；应用侧水位防止重复投递。文件消息在两秒内合并，最多保留三个原生对象；最终投递前再次检查窗口状态与偏好。不支持或投递失败不影响 Core 历史，也不自动循环重弹。

点击通知唤起主窗口，激活意图最多保留 16 个；Renderer 先订阅激活提示再读取 pending，完成已读写入后 acknowledge。原生消息关闭或弹出不标记已读。合并提醒进入文件消息分组，单项定位既有 Agent 会话或传输记录；目标不可用时保留摘要，不创建、重连或重试任务。

单项系统消息直接定位目标，不先打开消息抽屉；只有合并消息或目标不可用时才展示消息中心。审批文案简化为“有命令待审批”等类别提示，保留来源名称，具体操作在原审批窗口核对。

定位完成与已读、激活确认分步处理。后两步失败时保留待确认意图和错误状态，不重新打开抽屉；当前 Renderer 再次消费时只补交接，不重复切换页面。订阅停用后的异步定位结果不再更新抽屉或写入已读。传输定位会恢复全部筛选，目标行出现并获得焦点后才消费定位请求，避免列表晚到或连续点击同一任务时丢失定位。

两秒合并等待期间，Electron 用权威快照移除已经读过或清理的待投递文件结果；合并数量和点击目标均由剩余结果生成。

通知偏好保存在 userData 下 `notification-preferences.json`，严格校验总开关、AI 助手、文件、审批四个布尔开关；旧偏好保留原值并默认开启审批。通过同目录临时文件与 rename 原子更新，串行写入避免并发覆盖。它不随配置备份迁移。浏览器仅显示 Core 消息中心。

通知对外统一使用“AI 助手”，内部类型仍为 `agent`。列表分开展示结果、会话标题或文件名、正文概览或传输统计；系统通知正文包含相同摘要。标题最多 80 个 Unicode 字符、概览最多 160 个字符，由 Core 限长，Renderer 以纯文本展示。文件摘要保留传输量、完成数、跳过项及不确定结果。

审批使用独立 `approval` 来源和偏好，后台立即提醒，无需等待运行结束。Core 对账后移除已经失效的审批提醒，Electron 同时释放对应原生对象。点击时校验当前审批 ID 和有效期，并通过现有审批协调器选择该请求；主机密钥确认仍优先。点击通知不批准命令，也不重新创建失效请求。

原生通知遵循系统通知权限、勿扰模式及声音策略。测试使用受控通知对象验证策略，不将 `Notification.show()` 成功视为用户已看到消息；Windows、macOS 和 Linux 的打包体验需要分别验收。
