# 桌面环境与系统身份

正式安装包使用 **Termous / `com.termous.app`**，源码开发使用 **Termous Dev / `com.termous.app.development`**。两者可同时运行，用户偏好、浏览器会话、缓存、日志、单实例锁与通知入口相互独立。正式包开启 `webDebug` 或开发者工具不会切换渠道。

## 源码联调

在 `web` 执行 `pnpm dev`。首次启动使用本地 Electron 与 electron-builder 生成专属开发壳，放在工作区 `TEMP/desktop-development/<平台>-<架构>/shell`；后续按 Electron 版本和资源摘要复用。更新 Electron 或图标时自动重建，需要先关闭正在运行的开发版。`pnpm dev:clean` 只清理本平台生成缓存，不清理偏好或 Core 数据。

开发壳继续支持 Vite 页面热更新、主进程重启和 preload 重载。直接打开开发壳或点击旧开发通知时，只会激活当前开发实例；Vite 未启动时提示运行 `pnpm dev`，不会自行启动开发服务器或 Core。开发壳不保存 API 令牌、完整环境变量或正式登录状态。

默认连接外部 Core `127.0.0.1:8122`，保留 IDE 启动方式。外部 Core 不由前端关闭或重启，连接失败不会改连正式后台。前后端必须配置相同的 `TERMOUS_API_TOKEN`；默认联调值仅用于本机开发，正式托管 Core 使用随机令牌。

开发 Core 的 `TERMOUS_DATA_DIR` 应设为工作区 **`dev-data/.termous` 的绝对路径**。该变量是实际存储目录，Core 不会额外追加 `.termous`。启动外部 Core 时必须自行设置；仅给 Vite 配置不会改变已经启动的 Core。需要由开发壳托管测试 Core 时，可显式设置 `TERMOUS_CORE_PATH`；未指定数据目录则使用上述工作区路径，复用既有数据目录排他锁。

开发渠道禁用应用内更新和开机启动。正式包固定使用随包渲染资源和 Core，忽略开发页面地址、外部 Core 地址及 Core 路径覆盖；仍允许用户明确设置 `TERMOUS_DATA_DIR`。

`pnpm dev` 的应用内 Logo 和页面 favicon 与开发壳共用 BETA 图标，由 Vite 开发服务统一提供。正式构建继续使用正式品牌资源，开启 `webDebug` 不改变图标。

## 平台入口与迁移

- Windows：两环境使用固定且独立的 AUMID、通知 CLSID 和开始菜单入口。正式安装始终保留 `Termous.lnk`，桌面快捷方式与 PATH 仍可选。旧 AppId 仅用于定向迁移，安装升级 GUID 保持不变，保留原安装和用户数据。启动项迁移复制系统禁用标记，不自动重新启用。
- macOS：正式 `.app` 与开发 `.app` 使用各自 Bundle ID、产品名及图标。本轮不提供签名配置；原生通知仍受系统签名与权限条件限制，不能据此认定已完整支持。
- Linux：使用各自 `desktopName`、`.desktop` 入口与窗口标识。开发壳仅维护自身用户入口；正式 AppImage 保留既有发布方式。

注册失败暂停原生通知，应用内消息中心继续工作。普通点击和应用级激活统一去重；过期或失去映射的系统通知只唤起所属窗口，不执行消息里的业务动作。迁移只处理核对过归属的旧 Termous 入口，不清理其他 Electron 应用或系统图标缓存。旧身份的系统提醒和权限不会复制到新身份，必要时需重新允许通知。

## 验证边界

自动检查使用合成消息、虚拟注册表和临时目录，覆盖渠道拒绝、开发覆盖限制、快捷方式修正、通知重复激活与开机启动禁用状态。实际通知点击、托盘共存、安装覆盖升级和卸载必须在隔离用户或虚拟机验收；Linux 桌面与 macOS 签名环境分别验证。不要对真实账号或配置库做故障注入。
