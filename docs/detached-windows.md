# 独立窗口与业务状态宿主

## 进程与状态边界

独立窗口拥有自己的 Renderer、DOM、React 根节点和 AntD Provider。主 Renderer 的 `AgentWorkspaceHost` 是助手唯一业务宿主，持有 `AgentWorkspaceController`、草稿、队列编辑、附件文件及上传任务。两种视图均使用 `AgentSurfaceView`。Core 仍是持久化业务数据的权威来源，Supervisor / Worker 继续执行模型任务。

```text
Core / Supervisor / Worker
          ↑
主 Renderer：AgentWorkspaceHost
          ├─ 本地投影 → AgentSurfaceView
          └─ AgentSurfaceAdapter → 受限 IPC → DetachedAgentSurface → AgentSurfaceView
```

主页面切换、最小化或托盘隐藏不会销毁宿主。独立窗口存在期间，原生层按依赖宿主的窗口数量保持主 Renderer 活跃，最后一个关闭后恢复原节流设置。资源恢复与连接协调器也将小窗计入活动视图，避免主文档隐藏时停止观察。

独立 Renderer 没有完整 `window.termous`，不取得 Core 地址或凭据，也不装配业务 Gateway。纯浏览器与远控界面继续复用嵌入助手，独立窗口入口仅在本机桌面桥存在时开放。

## 交接与失败处理

状态流为 `embedded → opening → detached → returning → embedded`。

1. 打开时等待输入法组合结束，记录展示状态并冻结嵌入视图。截图只返回助手区域，不写磁盘；截图失败或超过 1.5 秒使用布局占位。
2. Main 创建隐藏窗口并返回新连接代次。宿主安装接收器后发送 `initialize`，随后才加载固定 Renderer，避免初始化请求抢跑。
3. 子窗口先订阅更新，再拉快照。完成视图初始化后发送 `ready`；宿主确认编辑权转移，Main 显示小窗。20 秒未就绪则销毁窗口，恢复嵌入视图。
4. 返回按钮先显示主窗口，并等待既有导航守卫；取消导航保留小窗。原生 × 仅显示主窗口当前页面，不发起页面导航。
5. 子窗口结束输入法组合、冻结编辑并确认最后输入及文件接收，再淡出内容。宿主恢复展示状态，在静态占位下挂载嵌入视图，覆盖层淡出后关闭小窗并释放编辑权。不等待模型运行或网络上传。
6. 交接失败恢复小窗编辑并提供重试。打开时使用截图渐变模糊与提示卡淡入，返回过渡只在输入确认成功后播放，取消导航不触发。动画使用 160–280 毫秒的短过渡；开启减少动画、页面隐藏时直接完成，其他原生窗口遮挡导致动画停滞时最多等待 400 毫秒，不无限阻塞交接。

子窗口崩溃恢复宿主已确认状态。主 Renderer 导航重载、崩溃、销毁或应用退出会销毁依赖窗口。窗口位置和尺寸只在本次应用运行中记忆，重启不恢复分离状态。

## 通信一致性与资源释放

- 窗口连接使用独立 `generation`，状态流使用独立递增 `sequence`，不借用 Core revision。旧代消息被丢弃。
- 初始更新先缓冲；快照到达后接续较新的更新。断档重新请求完整快照，并提供有限次自动恢复与手动重试。
- 状态按侧栏、当前会话配置、队列和各条消息分区。流式变化只传有变化的消息，不反复发送整段历史。
- 输入在视图中立即显示，以输入序号和宿主确认防止旧快照覆盖。切换编辑目标或提交前先确认输入；停止任务不受输入确认阻塞。
- 业务请求使用稳定 ID 去重，超时不自动重放业务操作。未确认的输入和文件在显式重试时沿用原 ID，已接收文件不会重复上传。
- 幂等读取与有序输入不长期保留响应；修改命令的去重记录保留到本代连接结束。图片内容不会累积在去重表中。
- 附件通过独立有界二进制请求传输：最多 8 个文件、单个 10 MiB、合计 20.5 MiB，宿主再执行现有业务限制。快照只包含元数据。预览按需读取宿主已发布目录中的内容；对象 URL 由当前视图创建并释放。
- 展示状态包含会话选择、搜索、队列编辑、面板展开、消息锚点及偏移、是否跟随底部和输入选区。菜单与未确认对话框关闭，浏览器原生撤销栈不迁移。
- 工具审批保留在主窗口，小窗展示等待状态与入口。业务通知和助手确认框由当前视图的 AntD 环境呈现。

## 新模块接入

1. 在 `common/contracts` 定义可序列化投影、明确的命令与校验器，避免传输函数、DOM、File、Blob 或 AbortController。
2. 在原生注册表添加模块类型、实例、标题、尺寸、宿主依赖和校验器。入口始终为固定 `surface=detached`，禁止任意地址、新窗口及 webview。
3. 在对应页面建立持久宿主和业务适配器，以 `useDetachedOwner` 接入生命周期；把业务状态与纯视图分离。
4. 在 `src/app/detached-surface/DetachedSurfaceRoot.tsx` 的静态表添加模块加载器。通过受限 `DetachedClient` 连接，不开放原始 IPC 或任意方法调用。
5. 为幂等读取明确声明响应保留策略；为写入保留去重，定义未确认状态和用户重试路径。
6. 添加生命周期、旧代消息、重复请求、断档、关闭交接和生产 preload 验证。

专用 preload 使用插件的标准多入口 API 单独构建为自包含 CJS。不能与其他 preload 拆出共享 chunk，因为 sandbox preload 不能 require 本地文件。未增加依赖补丁。

## 桌面自动化独立窗口

桌面自动化注册为 `desktop-workflow:workspace`，使用同一窗口管理器、受限 preload、状态流和交接状态机。窗口按钮、截图占位、返回动画及未确认请求回执提取到共享层，助手保留自己的业务适配和文案。没有新增另一套窗口 IPC，也不复用远程桌面的观察者窗口。

```text
Core：流程持久化与执行
          ↑
主 Renderer：WorkflowWorkspace
          ├─ WorkflowController：草稿、选择、版本与展示状态
          ├─ WorkflowExecution：运行配置、启动与控制请求、报告
          ├─ 本地投影 → WorkflowWorkspaceView
          └─ WorkflowSurfaceAdapter → 受限 IPC → DetachedWorkflowSurface
                                                       └─ WorkflowWorkspaceView
```

主窗口首次访问远程桌面后保留页面宿主；离开时释放桌面观看视图，流程宿主继续接收执行事件。独立窗口存在时，流程草稿不阻止主窗口切页。返回按钮经过主窗口原有的未保存导航确认；原生 × 只收回到当前主页面。原嵌入页面的“放弃修改”仍会重置流程宿主。窗口收回、主窗口最小化或隐藏均不取消 Core 中的任务。

- 草稿编辑所有者和输入序号由宿主确认，旧脚本的迟到输入不能覆盖新草稿。局部输入补丁按序送达，失败时保留该条及后续输入，显式重试沿用原请求标识，避免后续确认越过未送达的修改。流程选择、执行详情、目标桌面、运行配置、搜索、侧栏和步骤分支折叠状态随窗口交接；菜单、流程参数编辑弹窗和未确认提示不迁移。
- 启动与执行控制的请求标识由 `WorkflowExecution` 持有。响应丢失后显式重试使用原标识、参数和连接代次；窗口交接不重新发起任务，也不等待任务完成。运行参数的跨窗口交接使用内存投影与受限 IPC，不额外写入磁盘或日志。
- 执行链的全部展开、收起及单条例外由宿主保存，流式新增结果沿用全局选择，窗口交接后继续使用同一状态。动作详情只加载该次执行的固定版本，不回退到最新版本或草稿；绑定参数只显示名称，实际运行值不保存。版本不可用或请求失败时保留报告与控制入口，并提供显式重试；迟到的版本请求不能覆盖新选中的记录。
- 独立 Renderer 只接收目标会话与 profile 的必要摘要，不取得连接凭据、Core 地址或截图票据。媒体能力由 `WorkflowMediaHost` 限制：最多四个本窗口预览，仅允许读取当前草稿、版本、执行证据及当前报告固定版本引用的资源或本窗口刚上传的图片。上传限制 8 MiB，返回图片限制 32 MiB；关闭、崩溃和迟到预览均会清理观察租约。
- 交接会等待输入法组合、完整的媒体编辑过程（裁剪编码、上传、草稿写入）与输入回执，并冻结包含 Portal 在内的独立窗口控件。打开失败可重试；返回失败保留小窗及草稿。子窗口崩溃恢复宿主已确认状态，不保留尚未传回的输入。

开发验收与助手共用 `node scripts/remote/preview-server.mjs` 的 5183 服务，预览地址为 `/scripts/desktop/workflow-window-preview.html`，运行 `pnpm run test:workflow-window`。生产构建后运行 `pnpm run test:workflow-window:production`，实际加载 `dist/index.html` 的独立视图。夹具覆盖单实例、受限截图、草稿交接、主题语言、窄窗、后台编辑、导航取消、原生关闭、运行配置、执行控制与崩溃恢复；全部使用内存数据，不控制真实桌面。

### 深度复查与边界补强

保留独立 Renderer 与单一业务宿主的分层。通用层承担连接、窗口和交接生命周期，助手层承担输入、附件、反馈与状态投影；沿用现有公共入口和架构门禁。此前针对卸载、过期导航、状态断档及图片读取回调的修复继续保留。

- 连接释放后，已经入队但尚未开始的请求不再执行；已经开始的宿主任务继续完成。同步发送失败立即释放请求和定时器，同一请求 ID 可以显式重试。
- 最后一批输入确认后，宿主同步关闭子窗口的业务命令入口；返回动画期间的弹层操作不能绕过视图编辑锁。
- 已保存输入的回执丢失后，即使会话已经切换，也能确认原输入的重试；尚未确认的旧会话输入仍受所有权校验保护。
- 文件元数据与大小限制由发送端、接收端共用校验。空文件、超长文件名等无效选择不进入待确认队列，避免其被通信层拒绝后阻塞收回。具体文件类型和业务数量限制仍由现有附件策略检查。
- 非分离状态不生成跨窗口历史投影，收回后清理投影与签名副本，重新打开时序号继续递增。初始化消息缓冲和已关闭通知的键及时释放，移除未参与实际合同约束的泛型类型。
- 在其他主页面收回时，等待助手页真正可见后恢复消息锚点；隐藏期间的滚动事件不覆盖已保存的位置。返回动画中已可见、尚未解除编辑锁的视图提前恢复位置，避免动画结束后正文跳位。
- 新导航撤销旧确认时同步释放嵌入助手的待处理引用；独立助手的引用继续交给持久宿主，避免被主窗口切页或取消返回误清理。
