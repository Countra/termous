# 远程桌面与桌面自动化工作区

## 页面边界

`pages/remote-desktop` 组合远程桌面与桌面自动化工作区。对外文案使用“桌面自动化”，具体任务统一称为“流程”；内部类型和接口保留 Workflow 命名。

远程桌面复用既有会话栏：左侧保留会话标签，右侧提供“保留会话 · 数量”和“桌面工具”。保留会话列表通过原有 `selectSession` 恢复观看；工具菜单集中提供文件管理和桌面自动化，只展示单行图标与功能名。菜单按能力显示，无会话时仍可打开自动化；窄容器下触发器收为带可访问名称的图标。布局不新增顶部行或侧栏，也不覆盖桌面画面。自动化工作区铺满页面，右上角提供返回远程桌面的入口，执行记录保留在自动化内部。桌面全屏时隐藏自动化入口。

桌面工作区保持挂载，自动化首次打开后也保持挂载。隐藏区域同时使用 `hidden` 和 `inert`，切换不销毁查看器、编辑草稿或目录状态。进入自动化后焦点移至工作区，返回后回到桌面工具触发器，避免键盘焦点停留在隐藏区域。查看执行目标时，页面先调用既有自动化宿主接口，再选中目标桌面。

## 主机远程桌面配置

主机编辑与新建主机共用 `features/manage-remote-desktop/ui/RemoteDesktopProfileEditor`。顶部使用 VNC／RDP 协议单选卡，基本信息集中展示；连接、身份认证、显示与行为分别由共用组件维护，窄容器下依次排列。协议编辑器只提供协议专属字段及草稿变更，不跨协议引用界面和样式。

协议切换和直连／SSH 隧道切换继续使用既有草稿模型保留各自输入。密码仍采用保留、替换、移除三种独立草稿状态，提交及凭据持久化流程保持原有合同；界面不读取已保存的明文密码。

## 模块职责

```text
features/desktop-workflows/
  api/WorkflowClient.ts       类型化 HTTP、事件及图片读取
  model/                     定义编辑、坐标、目标、错误与数据订阅
    analysis/                独立预览、分析提交、应用校验与运行时准备
  ui/
    WorkflowWorkspace.tsx    草稿、保存、校验与工作区编排
    catalog/                 流程目录、搜索、执行列表与概览
    editor/                  工具栏、步骤树、截图和步骤属性
    execution/               启动对话框、运行控制和执行报告
    analysis/                分析弹层及工作流应用编排
    shared/                  来源、运行状态与表单样式
```

业务合同继续归属 `entities/desktop-workflow`；远程桌面会话归属 `entities/remote-desktop`，查看器、协议驱动和连接生命周期继续归属 `features/remote-desktop`。跨 Slice 使用公共入口，组件不构造 HTTP 地址，也不导入 Electron 实现。

会话栏操作由 `widgets/remote-desktop-workspace/ui/RemoteDesktopWorkspaceActions` 独立维护，接收文件及通用工具回调。桌面状态栏由 `RemoteDesktopStatusBar` 独立维护，只展示连接状态和质量。自动化工作区提供头部操作插槽，具体跨工作区入口由页面层组合；两个业务模块不互相依赖。独立桌面观看窗口及其 IPC、桥接合同、预加载和 Renderer 入口已移除；自动化宿主仍保持独立职责。

样式按组件共置，统一使用现有主题变量。`WorkflowEditorLayout` 组合执行链、截图和属性，复用已有分栏组件。两侧支持拖动、方向键调宽和双击重置，收起后完全释放空间，通过顶部带文字的按钮恢复。编辑区不足 860px 时使用“执行链／画面／步骤属性”原位切换，不使用侧边抽屉；选中步骤后返回画面。目录、执行链和属性独立滚动，截图不会因布局切换重新挂载。

展开宽度和折叠偏好通过既有 presentation 合同同步，独立窗口往返后恢复；仅在用户调整结束时写回尺寸，窗口缩放不覆盖偏好。尺寸约束集中在 `common/contracts/workflow-layout.ts`，窗口适配计算归属 `model/editorLayout.ts`，不改变流程定义、执行授权和媒体生命周期。

## 状态与交互

- 流程编排与执行记录由 `WorkflowWorkspace` 内部切换，查看记录保留草稿；加载另一流程、新建、复制或恢复版本仍经过未保存修改确认。
- 执行启动成功后直接进入该次报告；报告在返回编排时保持挂载并停止读取，保留未确认控制请求的标识，再次重试沿用原请求标识。
- 截图和启动共用显式目标。后台会话刷新不替换已选会话及连接代次；失效目标需要用户重新选择。
- 保存保留已有修订检查和编辑计数，保存期间完成的模板上传仍属于未保存修改。
- 目录监听既有 WebSocket 变更通知，再读取权威列表。列表、报告读取可取消；切换报告或返回编排后，忽略旧控制请求及查看桌面请求的迟到错误。
- 运行状态、执行结果和证据以 Core 返回内容为准；切换页面不取消运行，也不直接操作远程桌面。

## 后端与仓库协作

### 工作流文件交换界面

编辑器“功能”菜单按检查配置、版本文件及管理操作分组，文件操作集中在该菜单。未选中流程时，概览页提供导入入口；流程库只保留新建和搜索，不重复展示导入按钮。两个场景复用同一个交换控制器。导出先选择 ZIP、文件目录或独立 JSON，再由原生窗口选择位置；格式选择展示固定保存版本、步骤与资源数量，以及对应文件结构。包含模板图片时说明独立 JSON 不可用的原因，历史版本按其自身定义展示和导出。

导入预览区分原文件内容、保存名称与导入目标；整体更新展示替换范围并保留旧版本。传输进度、取消、提交不确定、修订冲突和成功回执继续由原控制器驱动。导出成功窗底部提供“打开目录”：ZIP／JSON 打开所在文件夹，目录格式打开导出的目录；打开失败保留成功回执并允许重试。保存路径只由主进程保管，窗口通过导出位置标识访问。窗口共用局部主题样式，正文独立滚动、底部操作保留，支持深浅主题、中英文、窄窗与键盘操作。

隔离视觉预览沿用 `node scripts/desktop/workflow-ui-server.mjs`，打开 `/scripts/desktop/workflow-ui.html?exchange`；可追加 `light`、`english` 参数。该预览只使用合成工作流、内存文件桥接和合成图片，不读取真实文件、不连接或操作桌面。实际 Electron 文件往返仍使用既有 `test:workflow-exchange:ui` 验收入口。

### 手动分析画面

工作台顶部保留“工作台／执行记录”导航和“画面分析”入口。分析通过独立大型弹层展示，未选择流程也可打开；`AnalysisSession` 管理专用只读预览和提交，`WorkflowAnalysis` 负责工作流应用上下文。`entities/screen-analysis/ui/explorer` 提供与工作流无关的画布、分页筛选、元素／OCR 详情、历史及参数面板。历史和结果共用右侧面板，通过最右侧竖向 Tab 切换；再次点击当前 Tab 收起，左侧不保留入口或占位。两种内容分别记住拖动后的宽度，双击分隔线恢复默认。窄窗口展开时显示对应内容，收起后回到画面；历史无桌面连接也可浏览。

普通分析在接受时固定全局设置；历史“重新分析”允许覆盖所选记录参数，默认强制推理，不修改全局设置。概览不夹带全文，列表按需分页，文字与检测分数分开筛选；查询不会重新推理或找回已过滤候选。长文字分段读取，诊断按需展开，只有显式导出才下载完整 v2 JSON。坐标与字段语义见[结果合同及示例](../../termous-aiService/docs/screen-analysis-v2.md)，任务、保留和查询规则见[记录中心](../../backend/docs/screen-analysis-center.md)。

列表与全量几何按同一查询版本发布，画布标框不受列表分页影响，OCR 使用自身的文字框和中心点。新任务只显示其自身原图和结果；切换目标或连接换代释放实时应用资格，保留只读历史。模板解码、裁剪、上传和草稿确认属于同一媒体任务；切换步骤后不应用旧操作。成功应用才把原图交给截图编辑器并关闭弹层，失败留在弹层。截图编辑器继续负责手动坐标、模板、范围和步骤 OCR 测试。

独立窗口通过现有媒体宿主桥接提交、概览、查询、取图和显式取消；宿主检查预览归属，请求重试沿用 `request_id`，取消使用分析 ID。窗口间只同步最近记录、筛选、选中项和视图偏好；读取取消传递到请求宿主。关闭弹层释放图片和结果正文，尚未保存截图的任务由分析会话有界等待捕获完成，已保存截图的任务继续后台执行。终态不轮询；历史只在可见且当前页有活动任务时轮询。前端不持有 Python 端口或管理令牌。历史不直接应用坐标；实时操作再次通过 Core 的 `action-context` 核对原预览、连接和尺寸代次以及五分钟有效期。

Core 的 `desktopworkflow` 服务组合控制服务、桌面来源与资产存储，维护脚本、不可变版本、运行报告和步骤结果。数据库由启动阶段的 `storage.Prepare` 协调，Goose 管理迁移；主配置库、Agent、Workflow 和审计具有独立归属及故障边界。参见后端的 `docs/database-migrations.md`、`docs/storage-layout.md` 和 `docs/desktop-workflows.md`。

Workflow 当前是本机能力，不进入云端配置同步或配置备份快照。`termous-service` 的 PostgreSQL、加密同步协议和 Goose 版本独立演进；`termous-mobile` 使用 Flutter／Kotlin／进程内 Go 核心，不能访问桌面开发数据。`termous-skills` 维护静态工作流和 MCP 合同，前端构建负责校验和打包；本次布局变更不修改工具合同。

## 验证

优先执行前端现有 `typecheck`、`check:architecture`、`lint:styles` 以及 Workflow、远程桌面页面与工作区的 UI 测试。关键回归路径：

1. 桌面与 Workflow 往返后，连接和草稿保持。
2. 编辑未保存内容后查看执行记录，返回仍可继续编辑；切换其他流程仍要求确认。
3. 保存、校验、启动、暂停、继续、单步及查看目标桌面沿用既有合同。
4. 检查执行证据、加载失败和刷新，以及中英文、浅深色和窄窗口布局。
5. 单步响应丢失后返回编排，再进入报告重试，必须复用原请求标识；切换报告后，旧请求失败不能影响当前报告。

内置浏览器可使用本地合成 Gateway 验证真实页面组件。此方式不代替 Electron 自动化宿主、真实 VNC／RDP 连接和 Core 持久化联调。

## 默认观看画质

入口为“设置 → 桌面与远控 → 默认观看画质”。“远程控制画面”统一设置设备桌面与经设备远控观看的 RDP 视频；“RDP 直接观看”和“VNC 画面”分别设置各自参数，每组预设只影响本组。“RDP 桌面效果”独立于公共画质区域。

默认值保存在观看端当前 Core；修改自动保存，仅在新建观看会话时读取，会话内调整不反写。所有分组与 RDP 桌面效果共用同一保存队列、修订号及失败重试，不修改被控端共享权限。实体受控组件复用公共像素／视频／RFB 合同；本机 Runtime 经设置网关、独立远控窗口经固定只读 IPC 获取默认快照。详见 [默认质量与生命周期](../../termous-remote/docs/desktop-quality-defaults.md)。
