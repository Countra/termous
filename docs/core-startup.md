# Core 启动与数据库状态

## 职责边界

数据库检查、初始化、基线接管和迁移仍由 Core 的统一数据库打开入口执行。桌面端不提供执行迁移的 HTTP 接口，也不通过日志文案猜测迁移状态。

- `common/contracts/startup.ts` 定义可供界面使用的启动快照，不包含 API Token 或业务数据。
- `electron/coreStartupProtocol.ts` 读取托管 Core 的结构化事件，验证协议、限制载荷并处理 UTF-8 分块。
- `electron/coreStartupState.ts` 管理所属实例、事件顺序、阶段超时和启动快照。
- `electron/coreProcess.ts` 保留子进程生命周期、HTTP 就绪校验与运行期心跳的所有权。
- `electron/coreRuntimeProbe.ts` 统一读取就绪与版本信息，请求期限覆盖响应头和 JSON 响应体。
- 启动窗口展示时序独立于真实迁移，不在 Core 中延迟事务或等待界面。

## 管道协议

Electron 为每次托管 Core 启动设置 `TERMOUS_STARTUP_PROTOCOL=1` 和唯一的 `TERMOUS_STARTUP_INSTANCE`。Core 在 stderr 输出以 `@termous/startup ` 开头的单行 JSON；普通 stderr 和 stdout 持续消费但不作为状态解析。

协议版本为 `1`。事件包含实例标识、PID、递增序号、实际时间、启动阶段，以及可选的数据库状态和安全错误信息。桌面端只接受当前实例和 PID 的新序号；旧实例、非法载荷、超长输出不能覆盖当前快照。每条记录最多 16,384 个字符，错误原因最多 2048 字符，详情最多 4096 字符，迁移文件只传文件名。

进程退出时最多等待 stderr 排空 500ms，优先保留最后的具体数据库错误。收到可信失败后立即展示错误，自动清理先给 Core 最多 12 秒自行释放资源并刷新日志，仍未退出才使用原有受控终止链路；用户主动退出可以提前结束该等待。错误一旦确认，后续通用退出错误或迟到的成功状态不得覆盖它。

`core.status()` 返回启动快照，`core.onStatusChanged()` 推送更新。订阅方先注册监听，再读取快照，按全局递增的 `revision` 合并。每次恢复重启有新的 `attemptId`，每次端口重试有新的 `instanceId`；不得将旧窗口的就绪通知用于新轮次。

## 等待与重试

普通进程启动最多等待 12 秒。确认进入数据库阶段后，不再用该期限中断检查、恢复或迁移。收到 services 阶段后重新计时，仍需 `/api/v1/runtime` 返回所属子进程的 PID 才能认为 Core 已就绪。

数据库阶段 15 秒未收到状态或心跳时提示状态暂时无法确认；处理达到 60 秒时提示等待较长。这两种提示不会自动杀死 Core 或重试迁移，心跳也不被解释成数据库操作已取得进展。用户退出仍走现有受控进程回收流程。

只有明确的端口冲突允许清理子进程后尝试下一个端口。数据库版本、迁移执行、权限或未知启动错误直接保留并展示；旧进程未确认退出时禁止启动下一进程。

外部 Core 模式没有所属子进程状态通道，快照阶段为 `external`，只展示连接状态；不能将连接异常推断成数据库升级失败。

用户退出会立即阻止正在恢复的 Core 继续启动，不等待长迁移结束；自动失败清理不能撤销该退出意图。状态订阅者重入初始化仍复用同一个启动 Promise，停止或重启后的旧 HTTP 心跳结果也不能更新新进程的状态。

## 排障与验证

启动窗口复用现有主题与外观。`startupPresentation.ts` 独立管理显示时序：数据库处理中至少展示 600ms，完成状态至少展示 500ms；从窗口实际可见并确认渲染时计时。已有启动窗口 650ms 最短显示时间与阶段时间重叠计算，不延迟 Core 的真实初始化。无需变更时不补播完成状态；新库显示初始化，已有数据库显示升级或接管。

数据库完成后仍等待 Core 的 HTTP 就绪、主窗口可显示和当前页面初始化完成，才进入工作区。失败立即打断展示计时；若数据库已经完成而后续服务启动失败，保留数据库完成结果，显示应用启动失败。恢复重启重新建立启动轮次；更新安装失败后的 Core 恢复失败保留错误界面，不自动退出而丢失原因。

启动窗口只加载专用 `startup-preload`，提供状态查询、订阅、渲染确认、复制诊断、打开日志和退出。所有操作由主进程校验所属窗口；打开日志不接受任意路径。启动窗口加载、preload 或渲染失败，以及可见后 5 秒仍无渲染确认时，回退到主窗口；主窗口的错误对话框同样显示具体原因和诊断操作。

诊断文本由主进程统一投影，包含应用与 Core 版本、启动轮次、最后阶段、已知的源/目标/已确认版本、失败迁移和安全错误详情。未知版本不猜测，已提交步骤不声称整体回滚。复制或打开日志失败提供反馈，退出始终可用。外部 Core 没有迁移事件，因此仅显示连接失败原因，不生成迁移结果。

Core 日志保存实际迁移事件、版本、迁移文件及真实耗时；Electron 日志记录进程实例、阶段变化和等待异常。日志和复制诊断不得包含 Token、密钥或完整 SQL 业务内容。

Electron 的 `electron-process.log` 位于应用日志目录，达到 512KiB 后保留上一份 `.1`。Core 的详细迁移日志继续写入既有 `termous-core.log`。状态管道与正式日志互不作为解析来源，界面展示的最短停留不计入迁移日志耗时。

定向测试覆盖协议拆包、末尾输出、慢迁移、阶段计时、实例隔离、具体错误保留及端口重试。运行期 HTTP 心跳和停止流程仍需回归，特别是恢复重启及更新失败后重新启动。所有数据库验证使用隔离夹具和统一 `TEMP` 目录，不使用真实 `dev-data` 执行测试迁移。
