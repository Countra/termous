# Agent 前端内存与交互回归（2026-10-24）

本次针对持续使用时的输入延迟、上滚回弹和 renderer 内存增长。保留已有资源引用、消息分页、模型上下文及工具执行机制，不增加内存告警，不使用强制 GC、周期重启或降低图片质量。

## 确认的问题与修复

| 问题 | 修复及边界 |
|---|---|
| 草稿更新重建事件数组，使消息投影失效 | `AgentContentWindow` 对未变化的内容字段直接复用；只保存已经裁剪的窗口引用 |
| 回调闭包变化使消息区和整个侧栏反复渲染 | 工作区稳定消息区回调；侧栏以稳定事件入口转发到最新业务上下文，权限和处理器变化仍生效 |
| Run 水位、用量更新重建所有侧栏条目 | 会话投影只在展示字段变化时更新；缓存只保留当前列表 |
| 同一长消息输出时重建全部工具视图 | 复用未变化的片段投影，并对工具行设置 memo 边界；状态、正文和图片变化仍更新 |
| 开发构建积累 React User Timing 记录 | 开发入口观察并消费 `Components ⚛` / `Scheduler ⚛` 记录，按名称清理；不清理业务性能记录、不修改 React 或浏览器 API。生产构建不安装该观察器 |
| 底部 96px 判定覆盖用户上滚意图 | 上滚滚轮、触摸、键盘和滚动条操作立即取消待执行的跟随帧；主动向下到末尾或点击“回到最新”才恢复 |
| 迟到的程序 scroll 事件重新开启跟随 | 无真实向下位移的尾部事件不能覆盖已经暂停的状态 |
| 跟随观察到加载按钮，虚拟片段高度变化引发跳动 | 观察实际正文容器；单会话共享交叉／尺寸观察器，片段使用实测外框高度及独立格式化上下文，卸载时注销 |
| 后台收回小窗时正文高度尚未恢复，历史位置被浏览器夹到顶部 | 保留未完成的恢复目标，在正文恢复高度后补齐；用户主动滚动立即取消，避免与用户争夺位置 |
| 独立窗口每次输入重新序列化全部历史片段 | 对不可变消息及片段使用弱引用缓存；收回独立窗口时释放缓存与发布副本 |

上述 UI 缓存不改变持久历史，不介入推理、审批、工具调用或图片输入策略。未使用全局无限 Map 保存历次消息版本。

## 实际测量

使用用户明确授权的 `dev-data/.termous`。以只读 SQL 统计定位长会话，然后通过真实 UI 读取；没有手工改写历史、修改模型配置或发送模型请求，正常启动迁移与兼容读取由应用执行。开发数据包含 80 个会话，其中测试长会话分别有 1,083 和 661 个原始片段。

环境为 Windows、Electron 43、React 19.2.7。In-app Browser 验证实际页面，补充使用 Playwright 驱动 Electron 原生 renderer 采样。性能宿主加载真实应用页面并连接开发 Core，但主进程是测试宿主，不是完整产品主进程。

内存值来自 `app.getAppMetrics()` 的 renderer `privateBytes`，单位 MiB；另采集 CDP 的 JS 堆及 DOM 指标。输入延迟为 `input` 事件开始至下一次 `requestAnimationFrame` 的时间，不包含输入设备或系统 IME 延迟。

| 场景 | 实际结果 |
|---|---|
| 调查基线：208 个字符，尚未修复侧栏及性能记录积累 | CPU 记录区间约 28.8 秒；renderer 约 466 → 1,851 MiB；JS 堆约 146 → 309 MiB |
| 仅修复侧栏后的诊断样本 | 输入约 5.8 秒，仍积累 23,093 条 measure，其中 22,232 条为 React 组件记录；renderer 达约 1,023 MiB |
| 开发构建：2,299 次输入事件、30 组往返滚动，约 61 秒 | 输入延迟 P95 22.5ms，最大 39ms；预热后约 842–868 MiB；没有超过 50ms 的长任务 |
| 开发构建长会话：相同操作，约 62 秒 | 输入延迟 P95 21.7ms，最大 34.6ms；未记录长任务，React measure 消费后为 0 |
| 生产构建长会话：10,659 次输入事件、6 次旧页加载、12 次会话切换及 30 组滚动，约 200 秒 | 输入延迟 P95 10.8ms，最大 21.6ms；后半段输入阶段约 538–552 MiB，包含分页／切换的整体峰值约 668 MiB |
| 生产构建：补充 120 次长会话切换及滚动，约 77 秒 | 后 60 次切换约 626–649 MiB，结束约 635 MiB；没有随切换次数继续线性增长 |

调查基线已经包含此前资源重构及本轮部分滚动修改，不是 Git HEAD 的完整 A/B 对照。开发构建的 CPU 采样开销和生产构建不同，不能把两个版本的数值当成严格对照。

`pre-sidebar.json` 仅前两次采样（`loaded`、`typed`）用于调查基线；后续采样受到调查期间热更新影响，不纳入修复前曲线或结论。

生产扩展场景有 13 次长任务，最大 86ms；120 次切换场景有 121 次长任务。切换和分页仍需进行页面挂载，不能将这两组结果表述为“整个测试零长任务”。重复输入阶段的延迟单独记录。

历史只按当前窗口读取：长会话首屏 74 个展示片段，约 30 个实际挂载；连续分页时展示片段最高 148 个，未加载全部 1,083 个片段。反复切换后的 DOM 数量约 2,900，未随切换累计。

In-app Browser 已实际验证：长会话上滚后停留、回到最新入口、草稿输入、工具结果展开、512×288 缩略图、1600×900 原图预览及关闭。图片 DOM 使用 Blob URL，没有 data URL。

## 验收限制

本次确认并修复了可复现的前端积累与渲染路径。上述短时测试不能保证完整软件在四小时／数天、多个真实模型并发运行时始终低于 2 GiB。

本轮未重做真实模型连续推理、四／八 Worker 长稳、完整生产主进程及双窗口长稳；独立窗口原生功能验收不能代替长稳。Go/Python 未做新的实现改动，因此没有将此前的 race 或模型测试记为本轮新通过项。下一步长稳应在相同指标下同时测量主进程、renderer、Worker 和 Core，并把开发构建与生产构建分开记录。

测试缓存沿用 `TEMP`，pnpm 缓存未调整；不触发远程 CI、发布或系统安装。

本轮启动的 Core、开发前端及两项验收静态服务均已停止，8122、5173、15173、5183 端口已确认释放；本轮创建的浏览器标签页已关闭，保留测试记录及开发数据。
