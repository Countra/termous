# Windows 安装信息发现

Windows 正式安装包在固定注册表路径保存安装元数据，供 Skill 或本机工具定位 Termous。记录由安装器维护，不替代 NSIS 原有的 GUID 安装键和系统卸载键，也不保存凭据、MCP 令牌、端口或用户业务配置。

## 稳定合同

- 1.0.0 按用户安装：`HKEY_CURRENT_USER\Software\Termous\Install`，旧应用标识为 `dev.termous.app`。
- 当前正式安装统一登记到 `HKEY_LOCAL_MACHINE\Software\Termous\Install`，应用目录仍可自定义。
- 当前 Windows 安装包为 x64，使用 **64 位注册表视图**；32 位调用方也应显式选择 `Registry64`。
- 查询时先检查当前用户记录，再检查所有用户记录。前者缺失、不完整或程序文件不存在时可继续检查后者；访问失败需报告，不当作未安装。

| 值名 | 类型 | 含义 |
| --- | --- | --- |
| `SchemaVersion` | REG_DWORD | 有效记录为 `1`；写入期间为 `0`，全部字段成功写入后才设为 `1` |
| `AppId` | REG_SZ | 固定为 `com.termous.app` |
| `DisplayName` | REG_SZ | 应用名称 `Termous` |
| `DisplayVersion` | REG_SZ | 本次安装包的应用版本 |
| `InstallLocation` | REG_SZ | 实际安装目录，不带命令行参数 |
| `ExecutablePath` | REG_SZ | `Termous.exe` 的绝对路径，不带命令行参数或外层引号 |

读取方只接受已支持的结构版本和应用标识；新增字段可忽略。安装元数据是定位信息，不是执行授权，也不是程序签名验证结果。未来其他自定义数据使用 `Software\Termous` 下的其他子项；`Install` 子项完全由安装器管理。

## 生命周期

- 首次安装、覆盖安装及升级完成时写入当前目录和版本。升级时旧安装成功卸载后清理旧范围记录，新安装再登记，避免切换用户／全机安装范围后残留旧版本；期间可能暂时无法发现应用，调用方可提示稍后重试。
- 卸载成功回调仅在应用标识与安装目录都匹配时删除当前安装范围内的 `Install` 子项。保留 `Software\Termous` 父项，不删除另一安装目录的记录或其他自定义数据，也不增加卸载页面。
- 写入失败不回滚已安装的应用，但安装器会提示发现信息未登记；静默安装写入日志。缺少 `SchemaVersion=1` 的记录不可使用。
- 更新验证应用使用不同 appId，不写入正式应用的发现入口。
- 1.0.0 已支持此发现入口，但没有独立桌面服务。更早的旧版、解压直接运行及开发环境可能没有记录；记录缺失时不要猜测安装目录。
- 用户手动移动或删除程序后，记录可能失效，因此启动前仍须校验文件存在。

## 服务与旧版升级

应用、Core、RDP 和 `termous-maintenance.exe` 留在用户选择的目录，服务载荷固定为 `%ProgramFiles%\Termous Service\` 下的 `termous-desktopd.exe`、`termous-desktop.exe`、`desktop-bundle.json`。应用目录及父目录不改 ACL；固定服务目录仅管理员和 SYSTEM 可修改。服务登记、维护记录和日志使用 `%ProgramData%\Termous\DesktopService`，与上述应用发现记录分开。

沿用原升级 GUID，支持 1.0.0 按用户／全局安装直接升级。默认使用有效旧目录，显式选择优先；跨账号提权按安装器所属会话识别原登录用户，不能用管理员的 HKCU 代替。不同路径的有效安装报告冲突，同一路径的多范围记录合并：全局登记决定归属，当前登录用户已保存的 PATH 和桌面快捷方式选项优先，缺失选项才沿用全局值。旧用户记录与快捷方式由新安装包助手处理，不要求先手动卸载。

“添加到 PATH”只操作交互会话登录用户，并记录新增条目的归属。更换目录后取消该选项，也会移除本安装器为该用户添加的旧目录条目；用户手动添加或旧版无法证明归属的条目保留。非交互部署不猜测个人用户。安装中断保留原目标目录与维护阶段，使用同一完整安装包继续修复。卸载先停止服务、回收进程，再清理归属明确的文件及登记；用户数据和诊断日志默认保留。协议和后端维护流程见 [桌面管理服务](../../backend/docs/desktop-daemon.md)。

## 安装进度与诊断

保留 NSIS 默认界面，进度文案按准备安装、安装应用、配置运行环境、配置桌面服务、完成安装展示；连续相同阶段不重复显示，临时目录和底层文件操作不覆盖当前阶段。进度条沿用 NSIS 原有机制，不表示剩余时间。

维护命令失败时，状态行固定显示“安装未完成”，不显示长路径。原生弹窗将简短原因、重试建议和日志位置分行显示；详细错误保留在日志中，日志不可写时改为显示有界摘要。安装详情也保留日志路径，关闭弹窗后仍可查找。静默安装返回非零退出码，不显示弹窗。日志保存为安装进程临时目录中的 `Termous-setup-{随机标识}.log`，包含阶段、维护命令、返回码、控制台摘要及助手返回的完整错误。中文错误通过 UTF-16 文件传递，避免控制台编码或输出长度截断。

恢复和临时文件清理结果追加记录，不替换首次失败原因。维护锁等待超过 30 秒时提示稍后重试，不终止正在运行的维护任务。安装日志独立于应用与 NSIS 临时载荷目录，关闭安装器后仍可按提示路径读取。它不包含认证密钥或用户业务配置；后续系统临时文件清理可能删除它，反馈问题时应及时保存。

## Skill 查询与启动

`termous-skills` 仓库的 `skills/termous-desktop/scripts/termous_desktop.py` 是唯一维护的桌面操作实现，使用 Python 3.9+ 标准库，无第三方运行依赖。在已安装的 Skill 目录下调用：

```text
python -B scripts/termous_desktop.py info
python -B scripts/termous_desktop.py status
python -B scripts/termous_desktop.py start
```

`info` 只查询元数据，`status` 进一步检查当前 Windows 会话进程，`start` 仅在用户明确要求且状态允许时发起一次启动。输出使用版本化 JSON，进程存在不代表窗口可见或 MCP 就绪；安装记录缺失、权限不足和启动未确认都应如实报告。实际调用应使用脚本的绝对路径，不再从文档提取代码或维护另一份查询实现。

同一入口支持 macOS 应用包及 Linux AppImage，平台发现范围和参数见该 Skill 的 `references/platforms.md`。Skills 构建、开发读取、生产校验和安装流程支持 `scripts/**/*.py`，继续执行原有的普通文件、路径边界及哈希校验。资源读取和安装不会执行脚本，也不为内置 AI 助手新增本机执行权限。

## 验收

在隔离 Windows 环境分别验证当前用户安装、全用户安装、含空格及中文的自定义目录、升级、卸载和更新验证应用隔离。检查新版本与路径刷新、原 NSIS 升级及卸载行为不变、另一目录记录与其他自定义子项不会被旧卸载器删除。自动检查不得读写真实注册表或运行生产安装器；只含临时文件的 NSIS 进度与故障夹具可以独立执行，但不能替代以上安装验收。
