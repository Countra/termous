# 设置中心接入

设置采用应用内弹层，打开时保留原页面及其草稿，关闭后返回原上下文。`SettingsDialog` 负责弹层、焦点恢复与关闭确认；`SettingsWorkspace` 负责分组侧导航、连续内容面板和页内保存边界。页面注册位于 `pages/settings/model/registry.ts`，集中声明标题、图标、所属模块、保存模式和向导锚点；业务资源仍由专用面板管理。

设置入口属于 `NavigationTarget`，不再属于主页面 `PageKey`。弹层遮罩不触发关闭，空闲时支持 Esc，未保存修改需要确认放弃；保存及内部编辑弹窗期间禁止关闭。模型编辑使用页内编辑区与统一保存栏；快捷键录制和数据导入导出等资源操作的忙碌状态同样登记到设置边界。设置打开期间阻止主页面连接快捷键和通知跳转；产品向导复用原锚点并保持设置面板实例。

## 页面保存边界

每个页面只采用一种保存模式：

- 通用、终端、连接、远程桌面、软件更新：自动保存，沿用各设置模块的提交与错误反馈；终端防抖输入在卸载时提交最后一次修改。
- AI 助手、模型服务、挂载、审计：统一保存。业务表单持有草稿和校验，页面通过 `SettingsEditorContext` 接管唯一底部保存栏、撤销和离开保护。保存期间禁用导航，取消离开保留草稿，确认放弃后卸载旧表单。
- MCP、快捷键、数据：独立资源操作。客户端、快捷键和备份各自提交，不与 AI 偏好的页面草稿混合。

连接页按 SSH 保活和后台转发分组；远程桌面页集中展示 SSH 隧道恢复、RDP 会话保留与系统文件剪贴板。隧道恢复仅重建 SSH 路由，不续接桌面会话。两页共用设置分组与字段布局，布尔控件仅提交自身字段；保留时间单独管理校验、失焦提交与冲突草稿，剪贴板继续按本机能力控制显示和禁用状态。

AI 助手的模型、上下文、并发、关联连接、Token 展示、执行限制和工具审批共用一份草稿。所有参数输入与失焦均不写入；点击统一保存后再校验并提交，开启跳过审批时先二次确认。普通参数与审批策略属于两个协议资源：逐项接纳成功响应，失败保留未完成修改，重试只提交尚未确认的资源，不宣称两者具备事务原子性。

`agentConfigurationDraft.ts` 负责转换、校验和三方合并，`useAgentConfiguration.ts` 负责草稿生命周期；界面分为模型参数、运行行为、执行限制和运行准备。外部更新只合并未编辑字段，重叠修改要求显式读取并核对最新配置。模型服务独立成页，返回 AI 助手页会重新读取资源，避免模型目录变化后使用旧选项。

模型服务使用可搜索服务选择器，连接配置、模型新增／编辑、目录中的默认模型选择均复用页面唯一保存栏。保存范围是当前编辑的资源；切换服务、连接／目录、返回模型列表时，未保存草稿需确认放弃。模型编辑直接占用原内容区，不再叠加编辑弹窗。连接测试、同步目录以及带确认的删除／恢复属于显式资源操作；测试连接要求先保存当前配置。连接校验与转换位于 `agentProviderDraft.ts`，请求通知位于 `useAgentProviderActions.ts`，目录默认项草稿位于 `useAgentDefaultModelDraft.ts`。后端资源与 revision 合同保持原样，服务已保存但模型同步失败时接纳保存结果并清除密钥输入，只提示重试同步。

模型服务的头部和提示条由 `ui/model-services` 内部组件维护，不扩散为跨功能表单框架。新增服务使用独立标题与返回入口，不显示尚不可用的目录页签；返回同样经过草稿保护。目录提供搜索、状态／来源筛选和直接编辑入口，更多菜单保留默认项、测试、移除和恢复操作。HTTP 警告紧邻连接字段，冲突与保存失败集中在编辑区前部，保留原有确认、恢复与失败后聚焦行为。

模型编辑期间收起服务选择区，编辑标题保留所属服务、刷新和返回目录入口。表单按模型标识、模型能力、运行参数组织，宽屏下能力与参数并排，窄屏按同一顺序纵向排列。字段布局和选项样式由 `AgentModelConfigurationFields` 独立维护，草稿、校验与冲突恢复仍由编辑容器管理。

主应用导航、消息导航和向导跳转同步遵守设置页的未保存及忙碌状态。设置保存接口和数据库结构保持原合同。

审计和挂载设置在未编辑时跟随最新确认快照，外部更新不会覆盖正在编辑的草稿；撤销修改恢复最新已读配置并清除过期失败反馈。重试冲突使用最新已读 revision，编辑基线仍保持原值，直到用户保存或撤销。AI 设置的运行检查与确认操作只显示等待状态，只有提交配置时才显示保存进度。

## 模块与依赖

设置页采用统一的小标题与轻底色区块，字段间距、边框和说明文字通过 `shared/styles/_settings.scss` 复用。各模块仍使用自己的 CSS Module 组织表单、列表和资源操作；共享样式只定义外观，不接管提交、校验或未保存保护。

- `common/contracts/settings-center.ts`：纯模块合同、版本信封和受控桌面 IPC；不导入 Renderer 或 Electron。
- `entities/settings`：快照解码、模块状态、版本合并、提交队列和通用面板读取 Hook。每模块保存一份确认值；表单草稿独立保留。重复快照不触发刷新，派生选择器保留其他模块的引用，避免无关事件重置草稿。
- `app/data-runtime`：装配 SettingsClient，Core 设置走 `/api/v1/settings`，桌面与浏览器设置分派到本机适配器。旧聚合 Settings 只从确认快照派生，供主题、语言、快捷键等消费者读取。
- `features/settings`：保留领域输入校验、专用表单和资源操作，挂载与审计复用统一状态 Hook；通知和开机启动不再直接调用偏好 IPC。
- `electron/settings`：固定模块注册、主窗口鉴权、严格请求校验、独立模块串行队列、版本冲突及变更事件。设置接口不接收 URL、文件路径或执行指令。

Core 变更订阅接收 `instance_id`、模块及 revision，断线后重连并重新同步。切换 Core 或运行实例会废弃旧请求；同模块请求串行，不同模块独立推进。发生 `SETTINGS_REVISION_CONFLICT` 时刷新确认值并保留草稿，排队的旧修改不自动重放。连接和补全控件只提交变动字段；连接适配器在模块队列执行时合成完整策略，保留 Core 的完整字段校验。旧版 Core 不支持新合同会明确报错，不回退旧路由。

暂时暂停订阅只使在途请求失效，保留已确认设置与草稿，避免网络故障把主题、语言恢复为默认值。首次确认 Core 实例同样隔离旧请求；并行启动的目录响应只有明确属于该实例时才可接纳。网关移除或替换时清理面板加载与错误反馈。AI 助手设置沿用原有冲突恢复交互，同时识别设置中心与业务资源各自的版本冲突错误码。

## 本机模块

| 模块 | 所有者 | 保存与生效 |
| --- | --- | --- |
| notifications | Electron | 复用严格校验和原子偏好文件，立即影响系统通知投递 |
| updates | Electron | 复用更新偏好文件和调度器；检查时间等运行数据放在 state |
| login_item | Electron／操作系统 | 仅显式修改时写系统启动项，随后回读；保留 macOS 待授权状态 |
| terminal_local | 浏览器本地 | 沿用 `termous.ui.terminal.sshSmoothScroll.v1`，默认关闭，存储不可用时内存降级 |

这些模块在 `localSettingsDefinitions` 中显式声明所有者、结构版本和 `backup: exclude`，均不参与配置备份。桌面偏好可在 Core 离线时管理；浏览器显示桌面功能不可用。通知激活、更新下载进度和安装等业务通道保持独立。旧通知偏好、更新偏好和开机启动专用 IPC 已移除。

## Core 与备份

Core 提供统一目录、模块 GET／PATCH 及 WebSocket 事件；PATCH 采用 `expected_revision + patch`，返回 `value`、`revision` 和独立的 `state`。主库 schema 38 使用模块记录；Snapshot 19 按模块保存结构版本与正文，继续支持 Snapshot 8～18 导入。语言、外观、终端、补全、连接、快捷键、窗口进入备份；挂载本机缓存、审计、Agent 和 MCP 设置保留目标机器值。

模型提供商、MCP 客户端、连接配置、字体文件以及缓存清理、审批、更新检查和安装均继续使用各自业务接口。

## 验证

模块状态测试覆盖串行写入、版本冲突、不同模块隔离和迟到响应；桌面测试使用内存 OS 适配器，不修改真实系统启动项。UI 回归覆盖保存失败、草稿保留、Core 切换和既有页面组合。各平台系统授权、原生通知和更新实际体验需要打包应用验收，受控测试不替代平台测试。

设置布局验收入口为 `scripts/settings/preview.html`，可通过已有隔离 Vite 服务 `node scripts/remote/preview-server.mjs` 访问 5183 端口。入口只使用内存网关，不连接开发数据库或系统偏好；`?light` 用于检查浅色主题，`?models` 直接打开模型服务，`?models&save-error` 用于验证一次保存失败及重试。模型服务预览由 `modelServiceFixture.ts` 提供独立内存 CRUD，不访问真实服务或保存输入的密钥。
