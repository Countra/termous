# Agent 工具图片请求兼容性

## 问题与证据边界

用户反馈：`termous.desktops.capture` 已成功，随后模型请求返回 HTTP 400、`invalid_request_error`、`1210`。该错误发生在模型请求阶段，截图成功不代表后续模型请求也已被服务端接受。界面的累计 Token 用量也不能直接作为单次请求超限的证据。

只读检查已授权的开发数据库后，未找到与截图时间、用量一致的失败 Run。现存的三条早期 `1210` 记录明确拒绝关闭思考，与截图的通用参数错误不同；不能据此更改当前模型的推理设置。近期同一配置存在多次截图及点击成功记录，因此也不能判断该配置普遍不支持图片。

代码检查确认：Pi 1.2.0 的 Responses 适配器将工具图片序列化为 `function_call_output.output` 中的 `input_text` / `input_image` 数组。原生 Responses 支持这种格式，但只实现字符串工具结果的兼容网关不能处理它。Chat Completions 适配器已使用文字工具结果与后续图片消息。

新增内存网关夹具对非字符串工具结果返回模拟 400/1210。修改前，经过实际 SDK 的 Responses 旧图片和资源引用两条路径均失败，Chat Completions 两条路径通过。这个实验验证兼容性边界，**不等同于复现截图所用上游的具体故障**。

## 实现与兼容性

- 在 Provider 边界使用独立的 `runtimeToolImageContext` 模块，将工具图片移到带工具来源标识的 `user` 图片消息；工具结果仍保留原始文字、调用 ID 与失败标记。
- 一个工具结果组全部提交后才追加图片。中间的系统工具声明不切断结果组，避免图片消息打断多个工具调用的结果配对。
- 只处理支持图片的 Responses 兼容网关请求。直连官方 `https://api.openai.com` 默认端口保留原生多模态工具结果；按解析后的主机、协议和端口判断，路径或相似域名不会误命中。纯文字、用户附件及 Chat Completions 沿用原路径。
- 图片对象及原始字节保持不变，不缩小图片、不丢弃图片、不改变有效图片选择策略，也不重复解码或建立常驻缓存。
- 投影只存在于单次请求。SDK 状态、消息持久化、检查点、资源引用、授权和实际输入执行均不改写。
- 通用 400/1210 继续作为终态失败，不切换 API、不猜测参数、不自动重放截图或鼠标输入。
- 图片物化前、异步读取完成后及 Provider 派发前检查取消。取消与读取完成竞争时，不继续读取下一张或调用 Provider；已取得的预算正常归还。已经派发的请求仍等待真实终态才释放预算，避免提前放行下一项图片请求。

原生接口依据：[OpenAI Function calling — Formatting results](https://developers.openai.com/api/docs/guides/function-calling#formatting-results) 明确允许 `function_call_output.output` 使用图片或文件对象数组。[Images and vision](https://developers.openai.com/api/docs/guides/images-vision#analyze-images) 同时支持独立的用户图片消息。兼容投影不意味着原生多模态格式有误，也不假定所有第三方网关都拒绝原格式。

## 验证

本轮使用现有依赖和隔离夹具，没有修改开发数据库，没有向模型服务发送用户历史或图片。

- 新增回归检查实际 SDK 序列化结果、旧图片和资源引用、原始像素一致、工具结果配对、多个图像及 MIME 类型、来源标识、失败状态、系统声明、源对象不变和资源租约释放。
- 复查发现并替换原集成测试中 CRC 不正确的 PNG 常量；替换图片已独立核验 PNG 块校验码和解压结果。新增官方端点及相似域名、协议端口边界、推理内容与配置保持、图片读取取消竞态、不同阶段失败和真实终态释放回归。取消竞态与官方格式保护均先以失败测试复现，再修复。
- 扩展原有分段回归：Responses 与 Chat Completions 均执行 25 轮、跨三个 SDK 循环，保持工具执行次数、追加指令、图片引用持久化及租约回收。
- 复查后的全量 Node 测试：`pnpm run test:node` 共 2,605 项，2,601 项通过、4 项因当前 Windows 不允许创建测试符号链接而跳过、0 失败。覆盖 Provider、上下文压缩、图片工作集、取消、背压、工作流、工具发现及前端状态等原有测试。日志位于工作区 `TEMP/agent-provider-image-review-node.log`。
- 类型检查、变更文件 ESLint、架构检查通过。
- 尚未执行真实上游模型对照或 Electron 桌面点击验收。现存记录不足以断言截图中的 `1210` 已得到唯一归因；后续若仍出现，需要对应 Run 的请求详情及上游错误字段继续定位。
