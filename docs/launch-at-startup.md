# 开机启动

“设置 → 通用 → 开机启动”控制当前用户登录系统时是否启动 Termous，默认关闭。只有正式打包的 Windows 和 macOS 桌面应用可操作；开发环境、浏览器访问和 Linux 中禁用并显示原因。

## 实现边界

- 状态来自 Electron 的系统登录项接口，不进入 Core 配置、配置备份或服务自启任务中心。恢复配置不会修改本机启动项。
- 主进程只注册 IPC，不在应用启动时写入系统设置。读取设置和窗口重新获得焦点也只读取状态；只有用户切换开关才提交修改。
- 主进程独立检查打包状态、开发环境、可信主窗口和布尔参数。执行路径、启动参数和启动项名称均由主进程固定，渲染进程不能指定。
- 修改后回读系统状态；关闭时同时确认已移除注册，不能将系统暂时禁用误判为移除成功。读取或修改失败时禁用开关，并允许重新读取。重试不会自动重放修改。
- Windows 使用当前用户的 `dev.termous.app` 启动项，并识别系统禁用状态。升级保留该设置；卸载脚本仅清理名称和可执行路径均匹配当前安装目录的无参数启动项。
- Electron 43 在 Windows 将查询路径作为命令行解析，查询时需引用完整路径以兼容空格；写入仍使用原始可执行路径。
- macOS 使用默认应用登录项。系统要求批准时，界面显示待批准说明；实际登录时启动仍取决于系统许可。
- 本设置只负责启动软件。端口转发等已保存服务的自动连接仍由现有 Core 自启中心负责。
- 开发模式限制仅通过标题旁的“开发模式”标识提示，支持悬停和键盘聚焦；正式环境不显示该标识。功能说明最多两行。

## 安全验证范围

自动测试仅向 IPC 注册器注入内存模拟的系统接口，界面测试使用模拟桌面桥接。不启动真实 Electron，不调用实际系统登录项接口，不读写注册表，不运行安装器。静态检查和构建不代表系统开机启动已验收。

## 正式版人工验收

1. 首次安装后检查开关默认关闭；开启后重新打开设置，确认状态保持。
2. 在包含空格或中文的安装路径中开启设置，退出应用，再注销并登录系统，确认只启动一个 Termous 实例。
3. 关闭开关后再次注销并登录，确认不再自动启动。
4. 在 Windows 系统设置中禁用启动项，再回到应用，确认状态刷新；macOS 出现待批准说明时，按系统流程批准后检查状态。
5. 升级应用后检查已启用状态保留；正式卸载后检查本安装目录的启动项被移除。
6. 运行开发版，确认开关禁用；开发版不得创建、删除或修改已安装正式版的启动项。

上述涉及系统设置的验收由用户执行，不在自动测试中运行。
