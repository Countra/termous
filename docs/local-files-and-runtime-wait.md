# 内置文件工具与运行时等待

本轮保持 Pi 1.4.0，Core／Worker 运行时协议同步更新为 20。已有工具名称、审批和外部 MCP 权限边界保持兼容；新增的 `wait` 仅供内置 Agent Runtime 使用。

## 文件合同

- `files.read` 保留字节 `offset/limit`，增加 `start_line/line_count`、`tail_lines`、快照游标和 `consistency=auto|snapshot|live`。默认按行读取 200 行，最多 2,000 行，每页正文最多 64 KiB。极小的旧字节限制沿用 UTF-8 四字节字符兼容处理。
- `auto` 在 64 MiB 编辑范围内生成固定快照；尾部和更大文件默认 live。live 是观察结果，不能作为编辑基线。尾部不扫描全文统计总行号。
- `files.search` 接受单文件目标，返回位置及有界续查游标。单次扫描最多 8 MiB／10 秒；超长正则行明确报告跳过，不伪装成完整搜索。
- `files.edit` 保留唯一精确替换，增加同一原版本的批量精确替换与行范围编辑。行范围必须提供 `base_version`，每次最多 100 项，原文与新文本合计最多 1 MiB，文件最大 64 MiB。插入文本中的换行应明确提供。
- 多项编辑全部校验后统一审批和发布；不模糊匹配、不部分执行。无变化仍复核当前文件，但不审批、不重写，返回 `changed=false`。
- UTF-8/BOM、未修改字节和文件权限保持；其他编码明确拒绝。混合换行只处理新增区域。

## 模块边界

Core `agentfiles` 负责流式扫描、稀疏行／字节索引、编辑区间、差异切片和平台发布。`localtools` 负责 Run 身份、读取视图、审批、资源预算和回执。快照和历史差异复用原内容对象存储与租约，数据库仅保存业务绑定和轻量清单。

活动视图与准备产物共享 1 GiB 预算，并限制 64 个视图／在途预留。Run 结束释放快照；旧代次撤销不释放新代次视图。应用关闭取消并等待在途操作清理。崩溃后不恢复旧执行资格，终态 Run 遗留视图由原资源回收流程清理。

审批期间不占目标路径锁。发布时重新检查 Run、文件身份、权限和完整摘要，在目标目录暂存后通过原有 Windows／Unix 发布机制替换。此操作不承诺对其他进程形成跨进程事务；发布后回执失败保持不确定，不重放。

审阅描述只包含身份、摘要和统计。审批页通过受鉴权 API 分页读取不可变版本；历史仅保留变更及有限上下文资源。审阅游标签名绑定版本、模式和范围。大文件不交给浏览器整体计算 Myers Diff；同一行的多个修改合并展示，长行分段显示。

Web 的分页加载与展示分离在 `shared/file-review` 和 `shared/ui/file-review`。主窗口与独立窗口按需请求正文，状态同步只传引用，当前页和返回游标数量均有界。旧内嵌文本审批继续展示。

## 等待语义

`wait(duration_seconds, reason?)` 接受 1～60 秒，使用异步定时器，不占用 Core 命令槽位。持久化后的 Steer 或已接入当前 Run 的桌面终态回执可以提前唤醒；停止和关闭清理定时器与监听器。返回实际耗时和原因，不作为任务完成证据。

已有任务应使用原任务等待／查询工具；没有可查询任务而需短暂停顿时才使用通用 wait。等待期间不主动请求模型。时间线本地计算倒计时，不逐秒保存事件。
